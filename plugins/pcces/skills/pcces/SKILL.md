# PCCES 預算書：讀、查、改

| 使用者要的 | 用哪支工具 | 速答 |
| --- | --- | --- |
| 整份預算書的章節、總價、金額對不對得起來 | `pcces_read_budget`（XML）、`pcces_read_db_budget`（資料庫） | `max_level=-1` 列全部，`response_format="detailed"` 多列單位數量單價 |
| 某個工項在哪一章、數量單價多少 | `pcces_find_items` | 名稱關鍵字或工項代碼前綴，只讀 XML |
| 某一項的明細、單價分析組成、哪些列能改 | 讀取工具帶 `item`（項次，例 `壹.二.2`） | 改值前一定先看這個 |
| 全案某種工料總共多少（鋼筋、混凝土、模板、人工） | `pcces_find_resources`（XML）、`pcces_find_db_resources`（資料庫） | 名稱關鍵字或工料代碼前綴 |
| 這台 PCCES 裡有哪些預算書 | `pcces_list_db_budgets` | 拿到工程代碼再交給其他資料庫工具 |
| 改數量或單價 | `pcces_write_budget` | 以 XML 為底稿另存新檔，再請使用者匯入 PCCES |
| 匯入後（或在 PCCES 改了值）重新總計 | `pcces_recalc_db_budget` | 會改寫那一本的計算結果：先跟使用者確認是哪一本，PCCES 要整個關掉 |
| 工具一再出錯、使用者說結果不對 | `pcces_report_issue` | 先問使用者要不要寫使用回報，同意才叫（〈使用回報〉） |

## 先拿到預算書

1. **XML（每台都能用，改值一定走這條）**：請使用者在 PCCES 開「預算書編製」→ 雙擊工程 → 選單「檔案 → 製作電子檔及列印報表」→ 選「預算書」→ 勾「工程會電子標單檔 xml 格式」→ 存到他找得到的資料夾，一路下一步到完成。中途問要不要「重新總計」「自主檢查」，只是匯出就選略過。檔名像 `(預算書)<工程名稱><工程代碼>_ap_bdgt.xml`，工具要的是這個檔的**絕對路徑**。
2. **資料庫（只在裝了 PCCES 的電腦上，不必先匯出）**：先叫 `pcces_list_db_budgets` 列出工程代碼，再交給 `pcces_read_db_budget`、`pcces_find_db_resources`。連不上時照工具回的訊息處理，或退回請使用者匯出 XML。
3. 使用者要你直接操作 PCCES 視窗幫他匯出：改讀 `pcces-desktop` skill，先徵得同意（電腦控制會接管滑鼠鍵盤）。

## 改數量或單價

1. 先用讀取工具帶 `item` 看那一項：是哪一種工項、單價是不是由單價分析算出來、組成哪幾列能改、不能改的原因。
2. 叫 `pcces_write_budget`，`edits` 照讀取工具給的範例寫：
   1. 沒有單價分析的葉項：直接改數量、單價。
   2. 有單價分析的葉項：數量可以直接改；單價要用 `component`（組成列的工料代碼）改組成的數量或單價，工具會重算分析單價與上層金額。
   3. 一般工料的單價全案共用：改一個分析，用到它的分析與資源統計會一起變，改之前先跟使用者講清楚影響範圍。
   4. 公式項（雜費、保險費、管理利潤、營業稅這類）不能改，要請使用者在 PCCES 裡改公式。
3. 新檔寫在底稿同一個資料夾，檔名 `<工程代碼>_edit_<日期>_<流水號>.xml`，原檔不動、不覆蓋任何既有檔。把回傳的完整路徑、總價變化、跟著重算的上層告訴使用者。
4. 使用者想讓 PCCES 裡分得出新舊兩份，就帶 `title_suffix`（例如「（改值）」），接在工程名稱後面。

## 匯入 PCCES、重新總計

1. 在 PCCES「專案目錄 → 專案建立‧轉入 → XML 電子檔轉入」選剛產生的檔。
2. 會跳兩個「非 PCCES 製作」的警告，都按確定，照樣匯入；專案目錄那一筆是紅字、備註「非【PCCES】製作」。工程代碼重複時 PCCES 自動加 `-01` 這類流水號。
3. 匯入後要重新總計，公式項與資源統計這時才更新，總價可能再變（`pcces_write_budget` 回報的是重新總計之前的值）。兩種做法：
   1. 叫 `pcces_recalc_db_budget`：先用 `pcces_list_db_budgets` 找匯入的那一筆（代碼重複時是加了 `-01` 這類流水號的那個），跟使用者確認是這一本，並請他把 PCCES 整個關掉，再叫。它直接叫 PCCES 自己的 DLL 重算，等於在畫面上按「重新總計」，回報前後總價與差額。
   2. 請使用者自己在 PCCES 開那份預算書，按工具列的「重新總計」。
4. 要交出去的版本，在 PCCES 做自主檢查（重新總計會清掉自主檢查結果）、再製作電子檔，由 PCCES 重新簽章。

## 規則（一定要守）

1. **PCCES 資料庫只讀，唯一的寫入口是 `pcces_recalc_db_budget`**：它經 PCCES 自己的 DLL 重新總計，其他資料庫工具只發查詢。不要用任何其他方式（SQL 指令、sqlcmd、別的程式）改資料庫——直接改資料表會繞過 PCCES 自己的檢核，壞掉的預算書在 PCCES 裡不一定看得出來。
   1. 叫之前先跟使用者確認是哪一本：它會改寫那一本的計算結果、清掉自主檢查結果，不能復原。
   2. 它拒跑時（PCCES 開著、版本跟驗證過的不同、舊算法工程）照錯誤訊息請使用者處理，或請他在 PCCES 畫面按「重新總計」；不要找別的路繞過。
2. **寫入一律產生新的 XML 交給 PCCES 匯入**，不改、不覆蓋使用者的原檔。
3. **不冒充 PCCES**：產出的 XML 標明是本工具產生、不帶 PCCES 的驗證碼與簽章。不要幫忙偽造或計算驗證碼，也不要把產出檔說成 PCCES 原檔；送件的版本一律在 PCCES 裡重新總計、自主檢查、製作電子檔。
4. 不操作 PCCES 視窗；要操作時走 `pcces-desktop` skill，而且先徵得使用者同意。

## 使用回報（工具出問題時）

回報檔只存在使用者的電腦，由他自己檢查後用 LINE 傳給提供這套工具的同事；工具不上傳、不寄出。

什麼時候問（任一成立）：
1. `pcces_` 工具回錯，換參數或換做法再試還是錯。連續回錯 2 次時，工具結果旁會附一段提醒（plugin 的 hook）。
2. 同一個步驟反覆失敗，或在幾種做法之間來回試錯。
3. 使用者說結果不對（總價、數量、項次跟他知道的對不上）。

怎麼問：
1. 先把手上這一步收在適合停的地方，不要為了問而打斷正在做的修正；只用一句話問，例如「這個問題要不要寫一筆使用回報，讓提供工具的同事改進？」
2. 同一個問題只問一次；使用者說不要，這個 session 就不再為這件事問。參數打錯、改一次就好的錯不用問。
3. 使用者同意才叫 `pcces_report_issue`。

寫什麼：
1. `summary`（問題摘要）、`attempts`（做了哪些嘗試，一項一筆、照先後）、`expected`（期望）、`actual`（實際）必填；`user_words` 選填，照使用者原話。
2. 不寫單價、金額、總價、工程名稱，也不寫機關、地點這類認得出是哪個案子的資訊：預算書可能是客戶內部資訊。要提就寫「某一項的單價」「這份預算書」。路徑裡的帳號名稱工具會自動換成 `<user>`。
3. 時間、外掛版本、Windows 版本、這台有沒有裝 PCCES 由工具自動補，不必寫。

寫完：
1. 把工具回的那兩句轉告使用者：檔存在哪裡（使用者「文件」底下的 `PCCES回報\`，檔名 `<日期>_<流水號>.md`），請他先打開看一下、刪掉不想給的內容，再用 LINE 傳給提供這套工具的同事。
2. 問他要不要幫他打開那個資料夾；要的話用 shell 跑工具回傳裡給的 `explorer.exe "<資料夾>"`（explorer 回退出碼 1 是正常的）。不要替他傳送。

## 已知限制

1. 資源統計只收工料；雜費、營業稅這類詳細表直接列的費用項用 `pcces_find_items` 找。
2. XML 版資源統計的數量、複價是匯出當時 PCCES 算的；被 `pcces_write_budget` 改過、還沒重新總計的檔會列出對不上的工料，請使用者匯入、重新總計後再匯出一次。
3. 資料庫工具連的是這台的 `.\SQLEXPRESS`（Windows 驗證）；PCCES 裝在別的執行個體時連不上，改用 XML。
4. `pcces_recalc_db_budget` 只接了 PCCES 的新算法、只認驗證過的 PCCES 4.3.1000.220；PCCES 更新後會拒跑，要等這個外掛更新。它在 PCCES 開著時一律拒跑（分不出 PCCES 開著哪一本），中途被中止的後果沒有測過。
